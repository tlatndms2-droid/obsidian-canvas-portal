# Canvas Portal

Obsidian Canvas의 자료를 포탈로 묶고, 필요한 내부 공간만 열어 작업하는 데스크톱 플러그인입니다.

## 설치

현재 버전 **0.4.10**, Obsidian Desktop **1.14.4 이상** 대상. 이번 버전의 실제 검증 환경은 Windows / Obsidian 1.14.5입니다.

1. [최신 릴리즈](https://github.com/tlatndms2-droid/obsidian-canvas-portal/releases/latest)에서 `main.js`, `manifest.json`, `styles.css`를 받습니다.
2. 사용할 Vault의 `.obsidian/plugins/canvas-portal/` 폴더에 세 파일을 넣습니다.
3. Obsidian을 다시 열고 설정 → 커뮤니티 플러그인에서 **Canvas Portal**을 켭니다.

BRAT 저장소 주소: `https://github.com/tlatndms2-droid/obsidian-canvas-portal`.

## 사용 방법

자료 선택 → 우클릭 → **Create Portal** → 이름 입력.
입장 카드를 선택하고 **Ctrl+Enter**, 또는 **Ctrl+더블클릭**으로 들어갑니다. 내부에서 포탈 카드가 선택되지 않은 상태로 **Ctrl+Enter**를 누르면 상위 Canvas로 복귀합니다. 일반 카드가 선택되어 있어도 동일합니다. 붉게 빛나는 퇴장 카드를 선택해 같은 조작으로 나갈 수도 있습니다. 최상위 Canvas에서는 포탈 미선택 시 이동하지 않습니다. 글 편집 중이거나 포탈을 포함해 여러 항목을 선택한 상태에서는 단축키로 이동하지 않습니다.

| 선택한 자료 | 생성되는 포탈 |
|---|---|
| 일반 카드 하나 또는 여러 개 | 일반 포탈 |
| 그룹 하나 또는 여러 개, 카드와 혼합 선택 | 그룹 테두리와 포함 카드를 보존하는 일반 포탈 |
| 기존 `.canvas` 파일 카드 하나 | 원본 Canvas를 여는 Link 포탈 |

- 입장하면 내부 전체가 보이며 맨 왼쪽 카드 하나가 자동 선택됩니다. 같은 가로 위치에서는 위쪽 카드가 우선이며, 퇴장 카드와 그룹 테두리는 제외합니다. 퇴장하면 상위 Canvas의 해당 입장 카드가 중앙에 보입니다.
- 포탈끼리 묶거나 내부에 새 포탈을 만들 수 있습니다.
- 일반 입장 카드는 왼쪽 큰 입장 아이콘, 오른쪽의 편집 가능한 이름, 발광과 위쪽 작은 아이콘·ID로 표시합니다. 카드가 작아지면 큰 아이콘과 여백도 줄어듭니다. Link에는 기존 사슬 아이콘과 연결 파일명이 표시되며, 본문은 별도로 편집합니다.
- 그룹을 선택하면 이름 입력창에 그룹 이름이 미리 채워집니다. 내부에는 원래 그룹 테두리도 남고, 내용을 꺼내면 그룹과 카드가 함께 나옵니다. 빈 그룹과 중첩 그룹도 보존합니다.
- 퇴장 카드는 이동·크기 조절만 가능하며 본문 편집·삭제·잘라내기는 차단됩니다.
- 메인과 각 포탈의 Ctrl+Z/Ctrl+Y 내역은 분리됩니다. 실행 취소 기록은 앱 재시작 시 초기화됩니다.
- 포탈 복제와 Ctrl+C/V는 내부 포탈도 독립 복제합니다. Markdown 파일과 Link 대상은 같은 원본을 참조합니다.

### 종료 후 위치 복원

Obsidian을 정상 종료한 뒤 다시 열면 각 Canvas 탭에서 마지막으로 보던 포탈·중첩 경로와 화면 중심·확대율을 복원합니다. 비활성 탭은 Obsidian이 실제로 불러올 때 복원됩니다. 같은 Canvas를 여러 탭에서 보더라도 각 탭의 위치를 구분하며, Link에서 돌아갈 원본 탭도 연결합니다.

복원할 포탈이 삭제됐다면 남아 있는 가장 가까운 상위 공간으로 돌아갑니다. 일반적인 수동 입장은 기존처럼 내부 전체 보기, 퇴장은 입장 카드 중심 보기입니다. 편집 커서·실행 취소 기록과 강제 전원 차단 직전 상태는 복원하지 않습니다. 위치 정보는 Canvas 카드 내용과 분리해 로컬 작업공간의 탭 상태에 보관합니다.

기존 Group 포탈도 일반 포탈로 표시하고 내부에 그룹 테두리를 복원합니다. 열어 사용한 자료를 정상 저장할 때 변환하며, 기존 내용은 로컬 안전 사본에 먼저 보존합니다. 열지 않은 Canvas는 일괄 변환하지 않습니다.

## 저장·해제·백업

가상 포탈 내용은 메인 `.canvas` 안에 저장되며, 평소에 포탈마다 별도 파일을 만들지 않습니다. **Link 내부의 일반 자료 수정은 연결된 원본 Canvas에도 저장됩니다.** 임시 퇴장 카드는 원본 파일에 저장하지 않습니다.

우클릭 → **포탈 해제 · 현재 자료 꺼내기**에서 현재 내부 자료를 배치합니다. 겹치는 곳은 차단되며 Esc로 취소합니다. Link 해제는 일반 파일 카드로 되돌리고, Link 카드 삭제는 원본 파일을 삭제하지 않습니다.

포탈을 선택하고 **Delete** 또는 우클릭 → **포탈 삭제…**를 누르면 다음 중 선택합니다.

- **내용 꺼내기:** 내부 카드를 현재 화면의 빈 곳에 배치하고 포탈을 없앱니다. Link는 일반 Canvas 파일 카드로 돌아갑니다.
- **내부까지 삭제:** 포탈·내부 카드·하위 포탈을 함께 삭제합니다. 원본 노트·이미지·연결된 Canvas 파일은 유지합니다. 일반 카드를 함께 선택했다면 그 카드도 삭제합니다.

## 다른 포탈로 이동

옮길 포탈 하나 또는 여러 개 선택 → 우클릭 → **다른 포탈로 이동** → 목적지 포탈 클릭. Esc로 취소합니다. 목적지 내부의 기존 카드 옆 빈 곳에 배치하며, 내부 카드와 연결선은 유지하고 옮긴 포탈의 바깥 연결선은 제거합니다.

Link 포탈을 목적지로 클릭하면 연결된 Canvas에 저장하고 원래 Canvas에서는 제거합니다. 원본 노트·이미지 파일을 옮기거나 삭제하지 않습니다. 자기 자신·하위 포탈·현재 Canvas 자신을 가리키는 Link는 목적지로 사용할 수 없습니다.

이동은 원래 공간에서 Ctrl+Z/Ctrl+Y로 되돌리거나 다시 실행할 수 있습니다. 이동 뒤 내부 내용이나 연결된 Canvas가 추가로 변경됐다면 그 변경을 먼저 되돌려야 합니다. 이를 통해 나중에 편집한 내용을 덮어쓰지 않습니다. 실행 취소 기록은 재시작 후 유지되지 않습니다.

## 백업

### 저장 중단 보호 (0.4.9)

플러그인이 켜져 있을 때 포탈 데이터가 있는 Canvas의 일반 저장과 파일 갱신은 임시 파일에 쓰고 검증한 다음 원본을 교체합니다. 저장 중 드라이브 연결이 끊기거나 쓰기가 실패해도 원본부터 비우지 않습니다. 이미 인식한 포탈 Canvas에서 포탈 데이터 전체가 사라지는 저장은 오류 알림과 함께 차단합니다. 플러그인의 정상적인 포탈 삭제·해제는 계속 사용할 수 있습니다.

Windows에서는 `%LOCALAPPDATA%/CanvasPortalSafety/` 아래에 Vault별·파일별 정상 내용 사본을 최대 20개 보관합니다. 포탈 Canvas를 열 때와 변경 저장 때 메인 카드·내부 포탈을 함께 보관하며, 빈 파일은 정상 사본을 대체하지 않습니다. 각 파일 폴더의 `source.json`에서 원래 Canvas 경로를 확인하고 `.canvas` 사본을 수정 시각순으로 확인할 수 있습니다. 복구는 사본을 먼저 확인하고 대상 탭을 닫은 뒤 진행하세요. 자동으로 원본을 되돌리지는 않습니다.

백업은 Vault 밖의 PC 로컬에 저장되므로 다른 PC에 자동 전송되지 않습니다. 공간 부족 등으로 안전 사본을 만들지 못하면 해당 저장도 실패로 알립니다. 파일당 20개의 보관 한도이며 파일 수에 따라 총 용량이 늘어납니다. 플러그인을 끈 상태, 포탈 데이터가 없는 일반 Canvas 및 Link 대상 원본, 다른 프로그램이 파일에 직접 쓰는 경우는 이 저장 보호의 대상이 아닙니다. 드라이브 자체 장애·전원 차단·다른 플러그인 조합 전체에 대한 무손실 보장은 아닙니다.

### 직접 지정하는 포탈 백업

설정 → Canvas Portal에서 Vault 안의 백업 폴더를 지정합니다.

- 최신 백업 1회분, 일반 Canvas 내보내기와 복구 정보를 함께 저장합니다.
- 폴더 지정·목록 열기만으로는 복원하지 않습니다.
- 복원은 포탈 내용을 백업 시점으로 바꾸며 일반 메인 카드와 연결된 원본 파일 내용은 유지합니다.
- 입장 카드가 없어졌다면 위치를 지정하고, 원래 Canvas가 없다면 다른 기존 Canvas를 선택해 복원합니다.
- 제거 준비는 최신 백업을 만들고 검증하며 플러그인을 자동 삭제하지 않습니다.

## 검증과 범위

0.4.10에서는 자동 테스트 51개와 빌드, 격리 Sandbox의 새 디자인·작은 카드·라이트/다크·한글과 여러 줄 편집·그룹 생성과 내용 꺼내기·복제·Undo/Redo·기존 그룹 변환을 확인했습니다. 같은 Sandbox를 재시작해 6개 탭의 일반·중첩·Link 경로와 화면 좌표·확대율, Link 복귀, 중복 탭 미생성 및 저장 내용 보존을 확인했습니다. 삭제된 포탈 경로의 상위 복귀, 파일 이름 변경과 기존 자료 안전 사본도 확인했습니다. 원본 Vault는 변경하지 않았습니다.

다른 탭 저장 시 현재 포탈을 유지하며, 숨겨진 내부 파일 카드의 경로 변경을 반영합니다. 백업 Canvas의 공백 형식만 바뀌면 읽을 수 있고 실제 내용 변경은 손상으로 차단합니다.

시험 환경에서 내부 전체 표시까지 100개 약 0.5초, 500개 2~3초, 1,000개 약 8초가 걸렸습니다. 일반 Canvas도 대량 표시 지연이 있으며, 이는 포탈 사용 전후의 동일 조건 성능 비교가 아닙니다.

모바일, 다른 Obsidian 버전 전체, 다른 플러그인 조합 전체, 실제 전원 차단은 검증하지 않았습니다.

## 개발

외부 패키지 설치 없이 Node.js에서 `npm test`, `npm run build`를 실행합니다. 빌드 결과 `main.js`와 `manifest.json`, `styles.css`가 설치 파일입니다.
